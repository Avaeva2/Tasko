# Вклад в проект

1. Создайте ветку для отдельного изменения.
2. Сохраняйте разделение основного приложения и `legacy`.
3. Для изменения поведения добавьте проверку соответствующего сценария; для механических правок достаточно существующих проверок.
4. Выполните форматирование, анализ и `flutter test` по [инструкции](docs/testing.md).
5. В pull request кратко опишите проблему, результат и проведённые проверки. Для изменений интерфейса приложите скриншот.

Не включайте действующие конфигурации, пароли, ключи подписи, дампы баз, приватные вложения и журналы с токенами. Используйте шаблоны в `config/`; результаты сборки и записи сценариев хранятся вне Git.

Рабочие аккаунты и базы не используются в автоматических тестах. Сетевые проверки запускаются явно в отдельном тестовом окружении.
